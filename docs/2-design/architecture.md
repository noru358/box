# 파일 구조와 흐름

← [문서 지도](../../README.md)

## 두 덩어리로 나뉜다
`src/engine.js`는 게임 규칙만 가진다. 맵을 읽고, 상자를 움직이고, 신호를 바꾸고, 누가 걸렸는지 판정한다. 화면을 전혀 모르기 때문에 node에서 그대로 불러 테스트할 수 있다.

`src/game.html`은 그 규칙을 보여 주고 조작을 받는다. three.js 3D 화면, 키보드·마우스 입력, 메뉴·일시정지·결과·기록 화면, 맵 편집기, 그리고 AI(직원과 숨은 상자)가 여기 있다. AI가 화면 쪽에 있는 이유는 플레이어 조작과 같은 자리에서 엔진을 부르기 때문이다(엔진 입장에선 사람 키 입력과 AI가 똑같이 `hop()` 호출이다).

`src/build.mjs`가 game.html 안의 `/*ENGINE*/` 자리에 engine.js를 그대로 넣어 `dist/index.html` 한 파일을 만든다. 외부에서 받는 건 three.js r128(CDN) 하나뿐이다.

## 덜어내기 스위치 (FEAT)
`game.html` 스크립트 맨 위 `FEAT` 객체. 꺼진 기능은 메뉴·도구줄에서 숨고 입력도 무시된다. 엔진에는 `colors`만 옵션으로 넘어간다(`wopt()`). 무엇이 꺼져 있는지는 [rules.md](../1-concept/rules.md) 끝.

## 폰(터치)
CSS `@media (pointer:coarse)`일 때 위 상태줄을 줄이고, 무대를 화면 높이에 맞추고, 아래 도구줄 대신 무대 위 버튼(`#touch`: 오른쪽 아래 돌아보기, 왼쪽 아래 조작 안내; 일시정지는 신호등을 가려서 위 상태줄 오른쪽에)을 쓴다. 세로면 `#rotate` 가림막을 띄우고 판을 멈춘다. 판을 시작할 때 전체 화면과 가로 고정을 시도한다(안드로이드만 됨).
- 숨는 쪽 입력: 키보드, 스와이프, 터치 탭, 도구줄 버튼이 모두 `hideInput(방향)`으로 간다. 스와이프와 탭은 화면 어디서든(버튼 위 제외, `document`에 붙음). 탭은 내 상자 화면 위치보다 위를 누르면 위 레일, 아래면 아래 레일(`tapMove`). 마우스 클릭은 레일을 옮기지 않는다.
- 찾는 쪽 스캔: 마지막 `pointerdown`의 종류(`lastPtr`)가 터치면 첫 탭은 선택, 같은 상자 두 번째 탭이 스캔.
- 카메라: `fitCam()`이 내려다보는 각도는 고정하고, 실제 칸 범위·신호등·(숨는 쪽이면) 직원을 화면에 투영해 가장자리 6% 안에 꽉 차도록 거리와 중심을 이분 탐색으로 맞춘다.

## 한 프레임에 일어나는 일 (game.html의 frame)
1. 남은 시간을 줄이고, 숨는 쪽이면 진행 방향키로 내 상자 속도를 정한다. 찾는 쪽이면 숨은 AI 셋이 판단한다(`botThink`).
2. 신호를 진행한다. 숨는 쪽 판은 AI 직원이(`signalAI` + 도장 근처 가산), 찾는 쪽 판은 플레이어가 Space로 건 신호를 노랑→빨강→초록으로 넘긴다(`seekSignal`).
3. 도장 판정: 상자가 자기 도장 칸에 들어오면 개수를 올리고 다음 도장을 띄운다.
4. `world.step(dt)` — 엔진이 상자들을 움직인다.
5. 엔진이 남긴 이벤트(`world.events`)를 화면이 읽는다: 덜컹(`thud`), 걸림(`frozen`), 신호 변경(`light`), 출고(`deliver`). 걸림이면 느낌표, 숨는 쪽 판이면 의심 점수.
6. 이벤트 목록을 비운다. 반드시 화면이 다 읽은 뒤에 비운다(v8에서 엔진이 먼저 비워서 생긴 버그가 있었다).
7. 상자·신호등·도장·표시를 그리고 렌더.

## 친구와 하기 (v13.1)
아티팩트 실시간 방(`claude.use('room')`)의 presence만 쓴다(이벤트 topic 권한이 필요 없다). 코드는 `game.html`의 "친구와 하기" 블록.
- 방장 = 찾는 쪽 판(mode 'seek')을 그대로 돌린다. 사람 상자는 `bots` 중 앞자리에 `remote`(그 사람 peer)를 달아 `botThink` 대신 받은 입력으로 움직인다. 나머지 판 처리(코인 먹기, 스캔, 끝)는 AI 상자와 같다. 0.1초마다 presence `snap`에 신호·시간·상자 전부(`world.packBoxes()`)·코인·숨은 셋의 코인 수·찾음/빠져나감을 싣는다(약 700바이트, 한도 4KiB).
- 상자 쪽 = mode 'hide'에 `net.role==='hider'`. 같은 맵을 `createWorld(..., {puppet:true})`로 띄워 벨트만 굴리고(일반 상자 결정·재입고 안 함) `snap`이 올 때마다 `world.loadBoxes()`로 덮어쓴다. 신호·코인·끝은 전부 snap을 따른다. 내 넘어가기는 바로 내 화면에 보여 주고 presence `q`(최근 8개 [번호, 방향])로 보낸다. 방금 넘어간 내 상자는 0.7초 동안 snap으로 덮어쓰지 않는다.
- 판 번호 `ep`로 새 판을 구분한다. 상자 쪽은 방장 presence에서 `as`(peer→상자 id)에 내가 있으면 시작한다.
- 알려진 한계: 입력이 직원 화면에 0.1~0.3초 늦게 닿는다. 노랑 끝에 누르면 내 화면에선 초록 때 넘어갔어도 직원 화면에선 빨강에 걸릴 수 있다. 방장이 일시정지하면 상자 쪽도 멈춘다.
- 시험: 실제 방이 아니라 가짜 방으로만 확인했다. 도구는 `tests/net/`(실행법은 파일 맨 위, `npm run check`에는 안 들어감).
- v0는 버릴 시제품이다. 다시 만드는 방식은 HANDOFF "멀티 다시 만들기".

## 저장
브라우저 localStorage에 네 가지: `box-custom`(내 맵 문자열), `box-diff`(난이도), `box-records`(최근 30판), `box-human`(사람 기록 최근 40판). 다른 기기나 다른 사람과는 공유되지 않는다.

사람 기록은 아티팩트로 열었을 때 공유 db에도 저장된다. 컬렉션 `plays`, 한 판에 문서 하나: `{v:1, at:시각(ms), map, win, got:찍은 도장 수, wins:[창...]}`(창 형식은 [ai.md](ai.md)). 규칙은 링크를 열 수 있는 사람은 읽기, 참여자(interact) 이상은 쓰기. 페이지는 열릴 때 최근 80판을 읽어 숨은 AI에 쓴다. db가 없으면(파일로 열기, 로그아웃) 이 브라우저 기록만 쓴다. Claude는 `ArtifactData`로 `plays`를 읽어 분석할 수 있다.

## 테스트
- `tests/engine.test.cjs`: 엔진만. 맵이 막히지 않고 흐르는지, 공유 문자열 왕복, 빨간불 걸림 판정, 보정값 범위, 다음 도장이 다른 레일인지.
- `tests/smoke.cjs`: 완성본을 가짜 화면(three.js와 DOM을 흉내 낸 빈 껍데기)에서 실행해 메뉴→(맵 만들기→기록)→스와이프 한 번=한 줄 이동→숨는 쪽 한 판→찾는 쪽 한 판이 오류 없이 도는지. `--full`을 붙이면 FEAT를 다 켠 판으로 돈다(`npm run check`는 둘 다). 그림이 맞는지는 못 본다. 화면이 들여다볼 수 있게 `window.__box`(mode, player, world, over, FEAT)를 열어 둔다.
